# C++ Simulator Speedup Plan

## 1. Goal

Make full ResNet18 `1x3x224x224` numerical validation finish in normal opt-in
test time.

Target:

```text
MGPU_FULL_RESNET18=1 MGPU_CPP_SIM=1 make full-resnet18
```

must finish and match PyTorch within:

```text
atol=5e-3, rtol=5e-3
```

## 2. Current baseline

Measured benchmark loop:

```text
Python: 48.26s
C++:     8.58s
speedup: 5.6x
```

Estimated first-conv cost:

```text
~2-3 billion interpreted ISA instructions
~0.3M instructions/second
~8,000+ seconds for first conv alone
```

Required speedup:

```text
roughly 1000x or more
```

## 3. Strategy

The main path is no longer optimizing the generic ISA interpreter. Instead,
use a dual-operator model:

1. Keep the mgpu ISA implementation as the source of truth for chip behavior.
2. Build native software implementations for expensive operators.
3. Verify both implementations against each other and PyTorch.
4. Use software implementations for full-model/large-model execution.

### 3.1 Dual operator model

For every expensive operator, maintain:

1. **mgpu implementation**

   - generated by `mgpu-to-isa`,
   - runs on the simulated ISA,
   - defines the target chip behavior.

2. **software implementation**

   - native C++ implementation,
   - direct loops or BLAS-style kernels,
   - used by the full-model runner,
   - does not interpret ISA instructions.

Rules:

- Operator-level tests keep using mgpu.
- Full-model or large-model runs use software.
- A differential test runs both and requires functional equivalence.
- mgpu remains available with `MGPU_CPP_SIM=1`.

### 3.2 Verification workflow

Verify every software kernel three ways:

1. **software vs mgpu**

```text
same input
same planned buffer offsets
output_sw = software kernel
output_mgpu = mgpu ISA kernel
assert allclose(output_sw, output_mgpu)
```

2. **both vs reference**

```text
assert allclose(output_sw,   pytorch_reference)
assert allclose(output_mgpu, pytorch_reference)
```

3. **software oracle for large shapes**

```text
large shape:
  software vs PyTorch

small equivalent shape:
  mgpu vs software
```

Recommended matrix:

| Dimension | Coverage |
| --- | --- |
| shape | small, medium, ResNet18-like |
| dtype | f32 first, then f16/bf16/f8/i8 |
| stride/pad/dilation | 1/1/1, 2/1/1, 2/3/1, 2/1/2 |
| bias | with and without |
| batch | 1 first, then >1 |
| layout | NCHW |
| malformed input | matching error classes where applicable |

## 4. Step-by-step software operator plan

### Step 1: Define the software operator interface

Create a native kernel registry.

```cpp
struct SoftwareKernelRequest {
  std::string op;
  std::vector<int64_t> input_shape;
  std::vector<int64_t> weight_shape;
  std::vector<int64_t> output_shape;
  std::vector<int64_t> strides;
  std::vector<int64_t> paddings;
  std::vector<int64_t> dilations;
  bool has_bias;
  int64_t input_offset;
  int64_t weight_offset;
  int64_t bias_offset;
  int64_t output_offset;
};

bool run_software_kernel(ByteMemory &global_memory,
                         const SoftwareKernelRequest &request);
```

Files:

- `cpp_sim/include/cpp_sim/software_kernels.h`
- `cpp_sim/src/software_kernels.cpp`

Exit:

- every operator has a stable identifier,
- unsupported operators fail clearly.

### Step 2: Implement the first software kernels

Start with operators that dominate full-model time:

- `conv2d`
- `matmul`
- `linear`
- `batch_norm`
- `relu`
- `max_pool2d`
- `avg_pool2d`
- `global_avg_pool`

Keep kernels direct, NCHW-first, and FP32-first.

Files:

- `cpp_sim/src/kernels/conv.cpp`
- `cpp_sim/src/kernels/matmul.cpp`
- `cpp_sim/src/kernels/norm.cpp`
- `cpp_sim/src/kernels/pooling.cpp`

Exit:

- each kernel has a C++ unit test against fixture values,
- no software kernel interprets the mgpu ISA.

### Step 3: Build the differential test harness

For each operator:

```text
software kernel -> output_sw
mgpu ISA kernel -> output_mgpu
reference        -> output_ref
```

Assert:

```text
allclose(output_sw, output_ref)
allclose(output_mgpu, output_ref)
allclose(output_sw, output_mgpu)
```

Files:

- `tests/operator_e2e/test_software_kernels_e2e.py`
- `cpp_sim/tests/`

Exit:

- every software kernel has a differential test,
- every operator has at least one mgpu-vs-software test.

### Step 4: Add software dispatch to the full-model runner

Add a software lowering path:

```python
run_operator_e2e(
    ...,
    lowering=lower_software_kernel,
)
```

The full-model runner should:

- compile the graph once,
- dispatch supported ops to software kernels,
- use the compiler-produced memory plan,
- retain op-level progress logging,
- fall back to mgpu for unsupported operators.

Files:

- `compiler/codegen/dispatcher.py`
- `compiler/mlir/mgpu_runner.py`
- `runtime/driver.py`
- `tests/operator_e2e/helpers.py`

Exit:

- a multi-operator model can run in software mode,
- operator-level tests still default to mgpu mode.

### Step 5: Implement a software conv fast path

This is the largest single win.

Implement direct C++ convolution for the ResNet18 scalar conv shape:

```text
for each output element:
  for c, ky, kx:
    load image
    load weight
    FMA
  optional bias
  store output
```

Specialize the common case first:

- NCHW,
- single batch,
- f32,
- stride/pad/dilation already encoded.

Files:

- `cpp_sim/src/kernels/conv.cpp`

Expected speedup:

```text
100-1000x for conv-heavy models
```

Exit:

- first ResNet18 conv benchmark drops from thousands of seconds to seconds,
- conv operator tests match Python.

### Step 6: Implement software matmul and linear fast paths

Implement direct FP32 matmul/linear kernels.

Files:

- `cpp_sim/src/kernels/matmul.cpp`

Expected speedup:

```text
large for final Linear and later LLM workloads
```

Exit:

- matmul/linear operator tests match Python,
- full ResNet18 final classifier runs quickly.

### Step 7: Implement software elementwise/norm/pool fast paths

Implement direct C++ loops for:

- ReLU,
- batchnorm,
- max/average pooling,
- global average pooling,
- elementwise add/mul.

Files:

- `cpp_sim/src/kernels/elementwise.cpp`
- `cpp_sim/src/kernels/pooling.cpp`

Exit:

- full ResNet18 non-conv operators no longer dominate execution.

### Step 8: Full-model validation gate

Run:

```bash
make full-resnet18
```

Require:

- full 224x224 forward finishes,
- logits match PyTorch within `atol=5e-3`, `rtol=5e-3`,
- cycles/profile counters captured,
- repeated runs deterministic.

## 5. Suggested commit order

```text
1. software operator interface
2. first software kernels
3. differential test harness
4. full-model software dispatch
5. software conv fast path
6. software matmul/linear fast paths
7. software elementwise/norm/pool fast paths
8. full validation
```

## 6. Optional later: optimize the generic interpreter

After software kernels cover full-model operators, the generic ISA
interpreter can still be improved for unsupported shapes and debugging:

- predecode every instruction,
- remove per-instruction lane allocations,
- parallelize SM execution,
- inline typed memory and ALU dispatch,
- remove global-memory copy overhead.

## 7. Risks

- Software kernels can drift from `mgpu-to-isa` output.
- Parallel SMs can introduce nondeterminism if profiles or shared state are
  updated unsafely.
- FP8/FP16 conversion differences between Python fixtures and C++.
- The generic interpreter must remain correct as fallback.
